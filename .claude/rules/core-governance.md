# 项目核心治理规则

> **地位：项目内的稳定规则源。**  
> 适用于规划、取证、实现、文档、测试、审查、Git 和环境相关任务。  
> 本文件不替代用户在当前对话中的明确指令；发生冲突时，以用户最新明确指令为准。

## 1. 先确认事实，再写结论

按以下优先级判断当前事实：

1. 当前被执行的代码、被加载的配置、测试和可定位 Git 状态；
2. 用户明确确认的环境事实；
3. 有权限维护者留下的可定位环境或部署证据；
4. 历史计划、设计、截图、临时导出、旧脚本阅读副本和候选部署资料。

禁止以下推断：

- 把仓库文件、本地测试、静态检查、候选 manifest 或设计文档写成远端已部署事实；
- 把脚本退出成功、Patch 生成/上传/挂载、HTTP 成功响应写成服务就绪、数据正确或游戏内已生效；
- 用未核实的设计资料覆盖运行代码或用户确认的环境事实；
- 因为资料缺失而猜测字段、脚本参数、部署状态或业务效果。

缺少决定性信息时，明确标为“信息不足”，说明缺少的**唯一关键证据**或提出一个最关键的问题；不要用长篇可能性列表填充回答。

## 2. 不扩大、不缩小用户要求

开始实现前，先在任务计划或回复中明确：请求结果、必须保留的能力、明确排除的范围、停止条件。

- 单个字段、条目或环境缺证，只阻塞受影响范围；不得借此关闭、拒绝、削弱或缩小其他已要求、已存在或已验证能力；
- 不得自行增加无证据支撑的产品限制；
- 发现此前判断错误时，直接承认并按证据修正，不通过叠加假设掩盖；
- 小任务采用最轻流程：范围简述 → 最小改动 → 验证 → 停止。复杂、多服务或长期任务必须维护项目内可更新的计划文档，不以聊天记录代替。

## 3. 环境、权限和失败处理

运行命令、安装依赖、访问网络、连接服务器、部署、拉取镜像或操作服务时，若出现权限、环境、网络、服务异常或命令失败：

1. 停止，不自行更换路径、绕过限制、反复重试或引入替代方案；
2. 简短说明失败现象、已确认的证据和最可能原因；
3. 给出 2–3 个明确处理选项；
4. 等待用户确认后继续。

例外仅限用户已明确授权的诊断范围；即使如此，也不得将诊断扩大为部署、覆盖、重启、真实执行或其他高影响动作。

## 4. 高影响动作必须由用户明确授权

下列动作没有用户当前明确授权时不得执行：

- 永久删除或覆盖文件、数据、配置或远端脚本；
- 连接 GS-1 / Muliu / 目标服务器，执行真实操作，重启服务，修改测试服或生产配置；
- Git commit、Git push、创建或发布外部内容；
- 绕过确认卡、租约、调用合同、权限检查或未知终态保护。

“本地实现”“通过测试”“生成候选部署物”均不构成上述授权。

## 5. 机器人执行、安全和敏感信息边界

- `config/muliu_script_catalog.md` 是机器人侧唯一执行许可；每一步必须精确匹配登记的 `path + args`、变量规则和风险等级；
- 知识文档、原始 Linux 脚本、脚本名称、自然语言近义词、历史经验和候选 manifest 均不能扩展调用能力；
- `route_scope`、`route_region` 是受控路由元数据，不进入脚本 argv；
- `submitted_result_unknown` 表示可能已提交但无可信终态：不等于失败，不自动重放，不要求用户重复确认；
- 真实 URL、账号、密码、Cookie、Token、IP、数据库连接、私有 profile、Task ID、工作目录及私有 route identifier 不得写入 Git、AI 输入输出、飞书卡片、`plan_json` 或 Gateway 审计文本。

当前代码若展示或记录任何 route identifier，必须作为**已发现的规则冲突**报告；不得通过改写文档把它默认为非敏感或已合规，除非用户明确重新定义其公开级别。

## 6. 文档规则

文档必须说明资料的：用途、消费者、输入/输出、运行期角色、风险、验证边界和维护责任。

文档职责固定为：

| 资料 | 唯一职责 |
| --- | --- |
| `README.md` | 项目入口、最短使用路径、权威入口和关键边界。 |
| `docs/architecture/current-project.md` | 当前实现、信任边界、已知限制与部署事实边界。 |
| `config/muliu_script_catalog.md` | 唯一机器人侧精确调用合同。 |
| `knowledge/` | 脱敏的用途、参数、影响、前置、恢复与验证边界。 |
| `deployment/gs1/` | 候选部署资料和人工核验清单。 |
| `docs/archive/` | 历史计划、历史设计和未接入的候选路线；不能作为当前操作依据。 |
| `SESSION-HANDOFF.md` | 阶段状态、阻塞与下一步；不承载稳定架构规则。 |

归档或删除前先检查实际内容和引用。永久删除必须等待用户明确确认；归档仍要保留醒目的“非当前事实”标记。

## 7. 验证与汇报

- 验证只报告其真实覆盖范围：本地测试、编译、生成器检查、文档检查分别说明；
- 检查失败时，报告确切失败对象和证据；不要把少数已确认问题概括为“旧测试”或转嫁分类判断给用户；
- 文档声称的当前行为必须能回溯至代码、测试、配置或用户确认的环境证据；
- 汇报简短、聚焦当前任务，不重复铺陈完整流程；
- 任何发现的规则冲突，都必须写入项目计划，并在修正后重新核验。
