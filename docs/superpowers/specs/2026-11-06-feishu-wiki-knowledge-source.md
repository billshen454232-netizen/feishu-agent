# 飞书知识库作为问答知识来源

> **状态：已取消（2026-11-06，用户决定）**
> **取消原因：** 机器人应用建在飞书个人版组织，公司组员所在组织不同；正式使用需在公司组织另建应用或迁移机器人，成本过高。以下为当时已核实的事实与设计，供日后重启参考。
> **日期：2026-11-06**
> **关联计划：** 项目计划看板（飞书知识库接入）
> **目标：** 组员在飞书里写文档即可被机器人学到，降低维护门槛；同时不降低现有检索质量。

## 1. 已核实的事实（2026-11-06）

- 测试知识库：`https://my.feishu.cn/wiki/M3cow54rLiAAwVktSmhcix3pnGb`（space_id `7704977193150991353`），一篇测试文档《B站-服务器相关操作 副本》。
- 机器人应用身份（tenant token）：`wiki/v2/spaces/get_node` 与 `docx/v1/documents/{id}/raw_content`、`/blocks` **已可读**；**列出空间内全部节点**（`wiki/v2/spaces/{space_id}/nodes`）缺 `wiki:wiki:readonly`（或 `wiki:node:retrieve`）。
- 测试文档：1609 个块，标题 H1–H4 结构完整（如「如何操作 → 重启服务器 → 只有 game」「合服 → 合服脚本运行失败」「数据库相关 → 清除合服数据」）；`raw_content` 是纯文本、**不含标题层级**，切段需用 `/blocks`。
- 测试文档含 10 个 IP、约 25 处密码相关内容、2 个 Mongo 连接串 → **入库前必须脱敏**。
- 主题与 catalog / `knowledge/` 重叠（清档、合服、清除合服数据等）。

## 2. 原则

1. **分层，优先级最低**：检索顺序「执行能力注册表 → 已审核问答 → `knowledge/` → 飞书知识库」；飞书段落只在前面没有足够依据时补充，不能压过已核对资料。
2. **只认指定空间**：只同步配置里登记的知识库空间；组员想让机器人学的内容放进去即可。
3. **注册表优先**：飞书内容与 catalog / 脚本行为冲突时，以 catalog 为准；冲突记录到审批台提醒维护人修改文档。机器人能执行什么，永远只看 catalog。
4. **必注出处**：引用飞书段落时注明《文档名》→ 小节、作者、更新时间并附链接；超过 180 天未更新标「可能过时」。
5. **脱敏**：IP、主机、账号、密码、连接串、Token 在入库时替换，回答阶段再过一遍现有的 `mask_sensitive_operation_data`。

## 3. 设计

### 3.1 同步（Gateway）

```text
定时（每天一次）或审批台「立即同步」
→ 列出空间节点（递归子节点，仅 docx）
→ 文档 edit_time 未变则跳过
→ /blocks 读取 → 按标题切段（H1–H4 路径作为段落标题；段落过长再按约 1500 字切）
→ 脱敏 → 写入 SQLite feishu_doc_sections（文档、节点、标题路径、正文、链接、作者、更新时间）
→ 文档被删除 / 移出空间时删除其段落
```

### 3.2 检索

- 段落级索引，沿用现有中文二元组 + 文档频率加权；
- 作为第四层来源，单独阈值；命中时在提示词里与 `knowledge/` 资料分开标注来源。

### 3.3 审批台

- 新增「知识来源」页：已同步文档、段落数、最近同步时间、同步错误、「立即同步」按钮；
- 冲突提醒（二期）：问答被判错、且引用了飞书段落时，记录为待处理。

### 3.4 评测（上线前）

用审批台「问答」中积累的真实问题，在「不接入 / 接入飞书层」两种配置下各跑一遍，对比：命中来源、回答是否正确、是否引入错误或冲突。评测通过再打开。

## 3.5 取消前已查明的权限阻碍

- 应用身份已开通 `wiki:wiki:readonly`；列空间返回 `131006 wiki space permission denied`：应用不是该知识空间成员；
- 应用授权知识空间需把「含机器人的**内部群**」加为空间成员；机器人当前只在一个外部群「111」中（`external: true`，群属公司组织），外部群不能加为成员；
- 知识库建在飞书个人版（`my.feishu.cn`，公开范围选项为「飞书个人版所有人」），与应用同属个人版组织 —— 单篇文档能读即因此；
- 公司组员在另一组织，个人版知识库对他们的可访问 / 可编辑性未验证；这是取消的直接原因。

## 4. 需要用户操作

1. 飞书开发者后台为应用开通 `wiki:wiki:readonly`（或 `wiki:node:retrieve`），并发布版本；
2. 确认测试知识库对应用可见（单篇已可读，列空间需上一条权限）。
