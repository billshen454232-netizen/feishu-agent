# 问答评审、纠正归档与知识文档回写

> **状态：已实现（2026-11-04，本地测试通过，未部署）**
> **日期：2026-11-04**
> **关联：** [执行结果确定性展示与典型故障库](2026-11-02-execution-report-library.md)（同一审批台、同一 SQLite）
> **不变原则：** 执行注册表（catalog）是能力的唯一依据；归档答案与 MD 资料只能解释能力，不能扩大能力，也不触发任何执行。

## 1. 目标

机器人的知识问答（规划器判定为 `kind=knowledge` 的请求）目前答完即止：答对答错都没有反馈，下次同样的问题可能再错一次，错误的 MD 资料也一直留在仓库里。

```text
问答 → 审批台「问答」页签人工评审
     ├─ 回答正确 → 归档
     └─ 回答错误 → 写纠正说明 → AI 重新回答（可多轮）→ 归档
归档的答案 → 以后类似问题作为参考答案交给 AI（热补丁，立即生效）
被纠正的 MD 资料 → 生成修改建议 → 人工采纳 → 回写仓库（从源头修复）
```

## 2. 范围

| 纳入 | 不纳入（首期） |
| --- | --- |
| 规划器判定为 `knowledge` 的问答 | `clarify` / `reject`（回复是固定提示，价值低） |
| 归档答案参与后续问答的检索 | 归档答案直接替代 AI 回答（仅「问题完全相同」例外，见 §5.3） |
| MD 文档修改建议与回写 | 程序自动改写仓库文件 |

## 3. 资料优先级

```text
执行注册表（catalog）  >  已归档问答（人工审核过）  >  knowledge/docs 下的 MD 资料
```

AI 回答时三者冲突按此顺序取舍；回答末尾列出实际引用的来源（已有 MD 来源列表，扩展加入归档问答编号）。

## 4. 数据模型（与 `message_jobs` 同一 SQLite）

### 4.1 `qa_records`：每一次问答

| 字段 | 含义 |
| --- | --- |
| `message_id` | 主键，对应 `message_jobs` |
| `question` | 提问（脱敏） |
| `answer` | 机器人原回答（脱敏） |
| `sources_json` | 引用的 MD 路径、归档问答编号 |
| `answer_model` / `answer_ms` | 回答所用模型与耗时（需求分析模型沿用 `message_jobs.planning_*`） |
| `status` | `pending` 待评审 / `correcting` 纠正中 / `archived` 已归档 / `dismissed` 不归档 |
| `created_at` / `reviewed_at` | 时间 |

发起人昵称沿用 `message_jobs.user_name`。

### 4.2 `qa_revisions`：每一轮纠正

| 字段 | 含义 |
| --- | --- |
| `message_id` / `round` | 所属问答、第几轮 |
| `correction` | 人工写的纠正说明（只需写「哪里错了」） |
| `answer` / `model` / `elapsed_ms` | AI 重新回答的结果 |
| `operator` | 操作人邮箱（Access 令牌）或 `ssh-tunnel` |

### 4.3 `qa_archive`：已归档的标准问答

| 字段 | 含义 |
| --- | --- |
| `archive_id` | 主键 |
| `source_message_id` | 来源问答 |
| `canonical_question` | 标准问法（AI 生成、人工可改） |
| `answer` | 最终答案 |
| `category` | 固定列表之一：开服 / 关服 / 清档 / 合服 / 热更 / 配置 / 查询 / 通用 |
| `keywords` | 关键词与同义词（AI 生成、人工可改），如 `对外, 外部体验, public, op` |
| `scripts` | 涉及的注册表脚本，如 `control_is_pub.sh, start` |
| `status` | `active` / `retired`（退回或已回写文档后下线） |
| `hit_count` / `last_hit_at` | 被引用统计 |
| `written_back` | 对应 MD 是否已回写修复 |
| `catalog_digest` | 归档时 catalog 内容摘要；catalog 变化后在页面提示「可能过时」 |

### 4.4 `doc_fix_suggestions`：MD 修改建议

| 字段 | 含义 |
| --- | --- |
| `suggestion_id` | 主键 |
| `archive_id` | 由哪条纠正归档触发 |
| `doc_path` | 如 `knowledge/docs/control_is_pub.md` |
| `original_excerpt` / `proposed_excerpt` | 原段落与建议段落（只针对有问题的几行） |
| `status` | `pending` / `accepted` / `ignored` / `applied` |

## 5. 流程

### 5.1 记录

`_process_registry_knowledge_decision` 回复后写入 `qa_records`（`pending`），记录回答模型、耗时、来源。写入失败只记日志，不影响回复。

### 5.2 评审与纠正（审批台「问答」页签）

```text
pending ──[回答正确]──────────────────────────────→ 归档确认
   │
   └─[回答错误] → 输入纠正说明 → [AI 重新回答] → 新答案（correcting）
                                    ├─ 仍不对：再写纠正，继续下一轮
                                    └─ [归档] → 归档确认
归档确认：AI 生成 标准问法 / 类别 / 关键词 / 涉及脚本 → 人工确认或修改 → 写入 qa_archive
pending ──[不归档]──→ dismissed（闲聊、一次性问题）
```

- 重新回答的输入：原问题、原回答、全部纠正说明、当前注册表与检索资料；
- 重新回答的结果**默认不发回群里**，只在页面展示；
- 归档确认这一步 AI 调用每条只发生一次；
- 已归档条目可编辑、退回（`retired`）、删除。

### 5.3 复用（方案 A：作为参考答案）

新的知识问答到来时，程序（不调用 AI）对 `active` 归档打分，取前 3 条连同注册表、MD 资料交给 AI：

```text
得分 = 问题与「标准问法 + 关键词」的重合度        （主要依据）
     + 问题提到了 scripts 中的脚本               （加分）
     + 类别命中（由问题中的类别词判断）           （加分，不作过滤）
```

- 中文按**字符二元组**计算重合度。现有 MD 检索把整句中文当成一个词，口语化问法容易匹配不上，归档检索不沿用这种做法；
- 低于阈值的不送；
- 例外：问题去掉标点空白后与某条 `canonical_question` **完全相同**，直接回复归档答案，不调用 AI，并注明「已审核答案」；
- 提示词要求 AI 优先依据归档答案，与注册表冲突时以注册表为准，并在回答中列出引用编号；
- 引用时 `hit_count + 1`。

### 5.4 MD 回写（从源头修复）

1. 一条「回答错误」的问答归档时，原回答引用过的 MD 标为「可能过时」；
2. 同一次归档调用中，AI 对这些 MD 的相关段落生成修改建议（只改有问题的几行），存入 `doc_fix_suggestions`；
3. 审批台「文档修正」列表展示原段落与建议段落的对比，可采纳、改写、忽略；
4. **回写由开发机完成**，Gateway 不改自己的 git 工作目录：开发机通过 Claude Code 读取已采纳的建议，在本地仓库修改 MD，人工看差异后提交、推送，Gateway `git pull`；之后把建议标为 `applied`；
5. 回写完成后对应归档标 `written_back`，可下线或删除；删除不会让错误内容重新出现。

## 6. 审批台改动

| 页签 | 内容 |
| --- | --- |
| 问答 | 列表：时间、提问人、问题、回答摘要、需求分析与回答的模型和耗时、状态、引用来源；筛选：待评审 / 纠正中 / 已归档 / 不归档 |
| 文档修正 | 待处理的 MD 修改建议（对比视图） |

沿用现有约束：服务端分页、前端缓存、页内刷新、Access 令牌校验、操作人审计。

## 7. 安全与边界

- 问题、回答、纠正说明入库前统一脱敏；
- 归档答案只能**解释**注册表已有的能力；AI 不得据归档答案生成执行计划，也不得扩大参数范围；
- 「完全相同直接复用」只用于问答，绝不用于操作请求；
- 手动放进 `knowledge/docs/` 的 MD 不经评审，按原样可信；`knowledge/scripts/`、`knowledge/references/` 继续不检索。

## 8. 实施顺序

1. 存储：四张表与迁移；
2. 记录：知识问答写入 `qa_records`；
3. 审批台「问答」页签：列表、正确 / 错误、纠正与重新回答、归档确认；
4. 检索：归档打分、注入提示词、完全相同直接复用、引用统计；
5. MD 修改建议生成与「文档修正」页签；
6. 开发机回写流程说明（Claude Code 读取已采纳建议 → 本地改 MD → 提交）；
7. 测试与小范围试用后调整阈值。

## 9. 验收标准

1. 每条知识问答都出现在「问答」页签，带提问人、模型、耗时、来源；
2. 回答错误可多轮纠正，每轮的纠正与新答案都可追溯；
3. 归档后，换一种问法提同样的问题，AI 回答引用了归档编号；
4. 问题完全相同时直接回复归档答案，不调用 AI；
5. 归档答案与注册表冲突时，回答以注册表为准；
6. 纠正归档会为被引用的 MD 生成修改建议；采纳并回写后，删除该归档，同类问题仍回答正确；
7. 任何问答流程都不会触发执行。
