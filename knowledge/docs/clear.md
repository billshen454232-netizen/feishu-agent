# clear

## 用途

对指定测试服执行清服流程。脚本会关闭游戏和 Zone 进程，调用逻辑游戏数据与 Zone 数据清理脚本，并可选地设置或删除开服时间配置。

机器人是否允许某个精确调用，只以 [../../config/muliu_script_catalog.md](../../config/muliu_script_catalog.md) 的当前合同为准。本文描述的高风险不等于禁止，也不代表 GS-1 已部署该脚本。

## 调用形式

```text
bash clear <server_id> [by|noby]
```

|参数|含义|
|---|---|
|`server_id`|明确的单个目标测试服编号。|
|`by`|清服后设置指定的真实霸业开服时间。|
|`noby`|清服后删除开服时间配置。|

不得因脚本可能有其他内部逻辑而自行添加参数或批量目标。

## 实际影响

脚本可能：

1. 停止游戏和 Zone 进程；
2. 清理逻辑游戏数据库数据；
3. 清理 Zone 数据库数据；
4. 按可选参数修改开服时间配置；
5. 对特定服务器走专用逻辑。

这是**破坏性高风险写操作**。错误目标、并发操作或重复执行都可能造成难以从脚本自身恢复的数据或服务影响。

## 前置检查、确认与恢复

- 先确认目标服、当前占用、备份、恢复方案和影响范围；
- 计划必须精确匹配 catalog，并经路由校验、防火墙和原请求人确认；
- 避免与启动、关服、改配置、合服或其他 Task 89 操作并发；
- 执行终态成功仅代表脚本层成功，不能直接表述为数据已清理正确、服务已恢复或游戏内环境已就绪；
- 具体恢复必须依赖已确认的备份、重建或启动流程，不能凭猜测重写数据。

## 部署与资料边界

- 脚本依赖同目录 `config.ini`、清理脚本、关服脚本与远程配置能力；
- 实际执行只应以经审核的 Linux 部署版本为准；阅读副本中的帮助文字和实际入口可能不同；
- 内部路由、数据库连接、账号和凭据不得进入 AI、飞书或 Git。
