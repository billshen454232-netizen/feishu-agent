# control_is_pub.sh

## 用途

对一个明确指定的测试服执行以下三项彼此独立的操作之一：

1. 开启调试 / GM 面板；
2. 关闭调试 / GM 面板并切换为发布模式；
3. 走外部体验开服脚本。

## 调用形式

```text
bash control_is_pub.sh <server_id> <k|re|op>
```

|参数|含义|实际动作|
|---|---|---|
|`server_id`|目标测试服编号|必须是明确的单服目标。|
|`k`|开启调试 / GM 面板|将 `IS_PUBLISH` 与 `NSLG_IS_PUBLISH` 设置为 `false`。|
|`re`|关闭调试 / GM 面板并切换发布模式|将 `IS_PUBLISH` 与 `NSLG_IS_PUBLISH` 设置为 `true`。|
|`op`|外部体验开服|在目标服调用 `release_bin/public_game.sh`。|

## 自然语言边界

- “开启 GM 面板”“打开调试面板”“关闭发布模式”只能对应 `k`；
- “关闭 GM 面板”“关闭调试面板”“开启发布模式”只能对应 `re`；
- “外部开服”“外部体验开服”“public_game 开服”只能对应 `op`；
- 普通“启动 / 开服”仍是 `start` 的职责，不能因为词义相近推断为 `op`。

## 实际影响与验证边界

`k` 和 `re` 通过受控配置修改脚本写入配置；脚本成功只代表配置修改命令返回成功，不能证明运行中的服务已重新读取配置，也不能证明游戏内 GM 面板状态已改变。

`op` 会触发目标服的外部体验开服流程。脚本返回不等于服务已完全就绪；仍需要独立状态查询或游戏内验证。

三项都属于高影响写操作，必须在群内展示精确计划并由原请求人确认。
