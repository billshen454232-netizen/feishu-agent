# starttime

## 用途

检查或修改指定测试服的 Debug 开服时间配置。脚本会处理远程配置中的 `debug_serverstarttime_config`，并可能创建、更新或删除对应的时间戳文件。

## 调用形式

```text
bash starttime <server_id> [timestamp|ctime] [--backup yes|no]
```

## 参数说明

|参数|含义|
|---|---|
|`server_id`|目标测试服编号。|
|未提供时间参数|仅检查相关配置是否存在及当前模式。|
|`ctime`|修改为使用当前时间模式；会将配置设为 `nil`，并删除已有的 Debug 时间戳文件。|
|`timestamp`|设置固定开服时间；可为纯数字时间戳，或脚本可解析的日期时间字符串。|
|`--backup yes`|在变更前备份远程配置和已有时间戳文件。|
|`--backup no`|不创建备份；这是脚本默认值。|

## 行为说明

|调用方式|是否变更|结果|
|---|---|---|
|仅传入 `<server_id>`|否|检查配置项是否存在及当前启用状态。|
|传入 `ctime`|是|修改配置为当前时间模式，并删除已有的固定时间戳文件。|
|传入固定时间|是|启用或添加相关配置，并创建/更新固定时间戳文件。|

日期时间字符串会由脚本执行环境解析；实际写入值应以明确的时间戳和执行结果为准，不能仅按自然语言日期推断。

## 实际影响

**高风险配置变更操作。** 它可能直接修改远程游戏配置，并创建、更新或删除远程时间戳文件。开服时间设置错误会影响测试环境的时间相关行为。

`--backup yes` 只会在变更前创建备份，不会自动验证新配置，也不会自动回滚。

## 前置检查与恢复

- 确认目标服务器编号映射正确；
- 确认变更后的开服时间业务含义和预期结果；
- 变更操作应显式要求备份，并记录变更前配置；
- 变更后应通过只读方式核对配置和服务实际表现；
- 如需恢复，应使用变更前的已确认配置或本次生成的远程备份，不应凭猜测重写时间值。
