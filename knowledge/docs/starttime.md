# starttime

## 用途

检查或修改指定测试服的 Debug 开服时间配置。脚本会处理远程配置中的 `debug_serverstarttime_config`，并可能创建、更新或删除对应的时间戳文件。

机器人是否允许某个精确调用，只以 [../../config/muliu_script_catalog.md](../../config/muliu_script_catalog.md) 的当前合同为准。本文不把自然语言日期、脚本原生功能或阅读副本视为额外调用许可。

## 调用形式

```text
bash starttime <server_id> [timestamp|ctime] [--backup yes|no]
```

|参数|含义|
|---|---|
|`server_id`|明确的单个目标测试服编号。|
|未提供时间参数|仅检查相关配置是否存在及当前模式。|
|`ctime`|修改为当前时间模式；会将配置设为 `nil`，并删除已有 Debug 时间戳文件。|
|`timestamp`|设置固定开服时间；可为纯数字时间戳，或脚本可解析的日期时间字符串。|
|`--backup yes`|变更前备份远程配置和已有时间戳文件。|
|`--backup no`|不创建备份；这是脚本默认值。|

## 行为与影响

|调用方式|是否变更|结果|
|---|---|---|
|仅传入 `<server_id>`|否|检查配置项是否存在及当前启用状态。|
|传入 `ctime`|是|修改为当前时间模式，并删除已有固定时间戳文件。|
|传入固定时间|是|启用或添加相关配置，并创建 / 更新固定时间戳文件。|

这是**高风险配置变更操作**。开服时间设置错误会影响测试环境的时间相关行为；`--backup yes` 只创建备份，不验证新配置，也不自动回滚。

## 前置检查、确认与恢复

- 确认目标服、时间业务含义、时区解释、可接受范围、备份位置和恢复方法；
- 计划必须精确匹配 catalog，并经路由校验、防火墙和原请求人确认；
- 日期时间文本的解析取决于实际脚本环境；不能从自然语言日期猜测最终写入的时间戳；
- 脚本成功不代表服务已读取新时间配置或游戏内时间已符合预期，须独立核对配置和服务表现；
- 恢复只能依据已确认的原值或远端备份，不能凭猜测重写时间值。
