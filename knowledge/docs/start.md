# start

## 用途

启动指定测试服的游戏服务；默认先启动 Zone 服务，再启动游戏逻辑服务。

机器人是否允许某个精确调用，只以 [../../config/muliu_script_catalog.md](../../config/muliu_script_catalog.md) 的当前合同为准。脚本原生支持的其他组合不得自行推断为可执行能力。

## 调用形式

```text
bash start <server_id> [noz]
```

|参数|含义|
|---|---|
|`server_id`|明确的单个目标测试服编号。|
|`noz`|不启动 Zone 服务，只启动游戏逻辑服务。|

## 行为说明

- 默认模式依次请求启动目标服的 Zone 服务和游戏逻辑服务；
- `noz` 模式只请求启动游戏逻辑服务；
- `4001` 使用专用启动逻辑，和普通服务器流程不同；
- 脚本自身启动后不会自动等待服务完全就绪。

## 前置检查与验证

这是**服务状态变更操作**。重复启动、依赖未满足或与其他运维操作并发时，可能造成状态混乱或掩盖真实故障。

- 确认目标服映射正确、目标处于预期停服或待启动状态，并且没有冲突操作；
- 计划必须通过精确合同、路由校验、防火墙和原请求人确认；
- 对已登记的启动合同，执行器会在脚本成功后等待受控时长，并追加固定 `basic_info.sh` 核验；仅独立行出现“开服成功”时，才可报告起服完成；
- 若脚本成功但后置核验未成功，不能称服务已就绪；应保留脚本终态与核验结果，并由后续受控查询或人工处理；
- 实际 GS-1 版本、SSH 权限和目标服启动条件须独立核验，不能由阅读副本证明。
