# start

## 用途

启动指定测试服的游戏服务；默认先启动 Zone 服务，再启动游戏逻辑服务。

## 调用形式

```text
bash start <server_id> [noz]
```

|参数|含义|
|---|---|
|`server_id`|目标测试服编号。|
|`noz`|不启动 Zone 服务，只启动游戏逻辑服务。|

## 行为说明

- 默认模式会依次请求启动目标服的 Zone 服务和游戏逻辑服务；
- `noz` 模式只请求启动游戏逻辑服务；
- `4001` 使用专用启动逻辑，和普通服务器的流程不同；
- 脚本启动后不会自动等待服务完全就绪，也不会自动做健康检查。

## 实际影响

这是**服务状态变更操作**。在服务已运行、启动依赖未满足，或同一目标存在并发运维操作时，重复启动可能造成状态混乱或掩盖真实故障。

## 使用边界

当前仅作为知识问答资料：

```text
不得登记到机器人执行资料；
不得由自然语言自动生成执行计划；
不得作为端到端验证脚本。
```

如需未来接入机器人执行，应先明确：目标服启动前状态、启动顺序和依赖、成功判定标准、失败后的回滚或人工介入流程。

## 前置检查与后续核对

- 确认目标服务器编号映射正确，且本地 `config.ini` 可解析目标；
- 确认目标服处于预期的停服或待启动状态；
- 确认执行环境具备脚本既有的远程访问能力；
- 发起启动后，应通过已审核的只读状态查询和启动日志确认结果；不要仅以命令返回成功作为服务已可用的依据。
