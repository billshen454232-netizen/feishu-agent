# 木流操作流程（脱敏）

## 资料范围

本说明从历史操作手册中提取操作类别、风险与核对原则。它不包含原始门户链接、账号、人员、服务器标识或环境映射；也不是脚本执行许可或远端部署证明。

是否可生成执行计划，唯一以 [../../config/muliu_script_catalog.md](../../config/muliu_script_catalog.md) 的当前精确合同为准。

## 操作类别

|操作类别|典型目的|风险等级|资料用途|
|---|---|---|---|
|基础信息与 Patch 检查|了解目标服状态、版本、日志或补丁情况|查询 / 检查|解释输出、触达范围与验证限制。|
|启动服务|恢复游戏或相关服务|服务状态变更|解释前置状态、启动依赖和后置核验。|
|关闭服务|正常停服、异常处置或批量停服|高风险服务中断|解释影响、恢复流程与强制停止风险。|
|清档与数据清理|为测试或环境重置清理数据|破坏性高风险|解释备份、恢复和数据范围核验。|
|开服时间管理|检查或调整测试环境时间相关配置|高风险配置变更|解释时区、备份、回滚和后置验证。|
|赛季与剧本配置|调整目标服游戏配置|高风险配置变更|解释值来源、重载 / 重启和回滚边界。|
|合服、调试或阈值类操作|历史手册中存在相关操作语义|高影响或待核实|解释术语，不根据历史写法推断参数或许可。|

历史手册中的类别不能扩大 catalog 合同；catalog 中存在合同也不代表该历史手册描述的脚本已在当前 GS-1 部署。

## 使用原则

1. 先确认操作目标、当前环境状态和影响范围。
2. 变更、停服和清理类操作必须确认前置条件、备份与恢复方式。
3. 脚本阅读副本、历史手册和 Linux 已部署版本不一致时，以已审核的部署版本为准。
4. 历史手册中的操作名称或参数写法不能直接作为机器人执行参数。
5. 脚本或 Muliu 的成功终态不自动证明服务就绪、数据正确或游戏内效果已生效。

## 与机器人执行的边界

知识问答可以解释某个操作通常用于什么、有哪些风险和应做哪些核对。只有 catalog 明确登记的脚本与参数模板，才能进入“生成计划 → 防火墙 → 路由校验 → 群内原请求人确认”的执行流程。
